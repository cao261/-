## 1. 已改（摘要，逐条细节见 commit message）

### 真缺陷
1. `auto_sync` 本机找不到 pwsh → 每轮同步都静默跳过重打 APK
2. 批注文件损坏被静默清空（读旧值→合并→写回，基数变空）
3. 符号词典损坏被空表覆盖（不可恢复）
4. 空正文重试把预算从 16000~32000 **砍**到 4096
5. 限流器 `min_interval` 在并发下完全失效（两线程同槽发车）
6. 上游 `{"error": "字符串"}` / `null` 让 `AttributeError` 逃出 `chat()`
7. `billing tier rate limit` 被判成配额耗尽 → 全局降格 15 分钟
8. `rendering.cancel()` 方法不存在，每次关阅读器静默 TypeError
9. 快照/诊断弹窗 Esc 监听永久泄漏（`{once:true}` 点 × 关窗时不摘）
10. 前端又一处裸 `DOMContentLoaded`
11. `askLLMStream` 不禁用按钮 → 连点 abort 掉自己
12. 三个写操作按钮无防重（双击生成两份工程/周报/踩坑）

### 性能
- `pdf_cache` 键去掉词典签名（后台认字不再废掉全库缓存）
- 3 处 pdfplumber / PyMuPDF 调用挪出事件循环
- `api_find_pdf` 改同步 def
- 有符号页不再白跑一遍 `extract_text()`
- 前端 `refreshPdfPageAnnoBadges` 从 O(N²) 变 O(N)

### 数据一致性 / 安全 / 清理
见 commit `4b922e8` message，含看板统计口径、原子写、`_safe_err` 统一、
死代码清理、`showToast` 时长参数等。

## 2. **发现了但故意没改**（改这些会动到契约，需要单独排期）

这几条是审计里价值最高的部分 —— 都验证过是真问题，但改动会改变**抽取输出**
或**同步/paper_id 契约**，必须单独一轮 + 全库复核，不能夹带。

### 2.1 `paper_text` 两处判据（会改抽取输出 → `EXTRACTOR_VERSION` 必 +1）
- **孤立短词被判成公式行**（`_is_mathish_line`）：`"in"` / `"of"` / `"as"`
  这种 2 字母残行满足「≤2 字母且 ≤12 字符」→ 判为公式行；若相邻还有 `[?]`
  行，`_mark_broken_formulas` 会把它并进 `⟦FORMULA⟧`，**正文就此消失**。
  与 §4.12「正文优先」同源的漏网。
  修法：纯 `[a-z]{1,3}` 且不含数字/括号/关系符时返回 False。
- **短双栏页直接退回 plain**（`len(words) < 40` / `len(below) < 30`）：
  两栏末页、只有图注的页会走 pdfplumber 默认顺序 → **两栏逐行交错**，
  正是 §4.5 要修的病。应改成比例判据 + 补一条 39 词的合成双栏用例。
- 两处「公式段最长行数」阈值不一致（`>10` vs `>12`），同一段 11~12 行碎片
  在两条路径上得到不同结果。

**这三条改完的代价**：所有译文快照作废重翻（用户要重新等翻译）。
→ 建议攒到一次改动里一起做，并照 §4.12 的做法跑全库 24 篇 / 391 页前后对比。

### 2.2 同步层
- `api_sync` 是 `async def` 但通篇同步 IO（写文件 / `_sha256_file` 读 MB 级
  / 可能复制 256MB PDF）。整体挪 `asyncio.to_thread` 是对的方向，但要确认
  `_write_local_progress` 等不依赖线程局部状态。
- `_sync_root()` 无缓存，每个批注请求要走 2~4 次文件系统探测（读 env →
  坚果云 `iterdir` × 3 → 解析 `UsersMap.json`）。可按 env 值做 memo，
  但 `tests/conftest.py` 会逐用例 monkeypatch，**必须按 env 值作 key**。

### 2.3 重复代码（能省 ~200 行，但都在热路径上）
- `app.py` 翻译主循环 + 漏译重译两处几乎逐行相同（~110 行）；抽
  `_translate_chunks()` 需跑 `test_translation_robustness.py` 全量回归。
- `app.py` 原子写 JSON 6 处各写一遍（本次只补了 3 处裸写，没统一）；
  抽 `_atomic_write_json()` 是纯等价重构，可以随时做。
- `app.py` 的 djb2/base36 与 `merge_changes.py` 各一份；`_paper_id_for` 的
  docstring 说"复用 merge_changes 的实现"但实际调用本地版本。抽公共模块
  会触及 `test_paper_id_contract.py` 的契约，需谨慎。

### 2.4 前端
- 40 处裸 `fetch`，其中 12 处「先 `json()` 后查 `ok`」—— 服务端 500 返回
  HTML 时 `.json()` 先炸，真实状态码丢失，用户看到 `Unexpected token '<'`。
  抽 `postJson()` 能一并修掉，但改动面大（12 个调用点）。
- 跨章节问答的勾选状态每次切章节被重置（`renderCrossQASectionPicker`）。
- 阅读器无法用键盘关闭（只有右上角 ×）。
- 诊断面板 `escapeHtml(e.status)` 漏了一处（目前数据是固定枚举，属加固）。

### 2.5 有产品用途、需产品决策
- 3 处 200 响应会回吐本机绝对路径（`abs_path` / `root` / `dir`）。
  `root` 用于让用户确认"我的同步目录在哪"，删了会掉功能；
  其余两处前端不依赖，可以去掉。

## 4. 对方设备（30461）需要注意

1. `pull` 之后**重启服务**才生效（后端改了 6 个文件）。
2. 前端是 `no-store`，刷新即生效。
3. `pdf_cache` 的键变了 → 本机缓存会全部重建一次（27 篇 × 2.7s ≈ 72s，
   一次性，之后恢复）。缓存不进同步，两台各自重建，互不影响。
4. `EXTRACTOR_VERSION` **没有动**（仍是 5）→ 译文快照不会作废。
5. 看板「精读译文」的口径变了：现在只数**真有译文**的页，且本地+同步取
   最新的那份。若数字比之前小，是因为之前把未翻的占位页也算进去了。

## 5. 下次改动前的三条提醒

1. **`_wireModalDismissals` 现在有幂等语义**：`closed` 标志 + `overlay._dismissCleanup`。
   新增弹窗只要调它即可，不要再自己挂 `document.addEventListener("keydown")`。
2. **`pdf_cache` 的键不含词典签名，前提是"抽取层不读词典"**。
   `tests/test_pdf_cache.py::test_extractor_does_not_need_the_glyph_dictionary`
   会检查 `extract_text_from_pdf` 的签名和源码。如果将来要在抽取层里直接用
   词典，那条测试会先红 —— 那时必须把词典签名加回去。
3. **限流器的 `_next_allowed` 是并发正确性的关键**，不要在 `acquire()` 里
   改回"按上次实际调用时间算间隔"。

## 1. 已改（摘要，逐条细节见 commit message）

### 真缺陷
1. `auto_sync` 本机找不到 pwsh → 每轮同步都静默跳过重打 APK
2. 批注文件损坏被静默清空（读旧值→合并→写回，基数变空）
3. 符号词典损坏被空表覆盖（不可恢复）
4. 空正文重试把预算从 16000~32000 **砍**到 4096

9. 快照/诊断弹窗 Esc 监听永久泄漏（`{once:true}` 点 × 关窗时不摘）
10. 前端又一处裸 `DOMContentLoaded`
11. `askLLMStream` 不禁用按钮 → 连点 abort 掉自己
12. 三个写操作按钮无防重（双击生成两份工程/周报/踩坑）

### 性能

### 2.1 `paper_text` 两处判据（会改抽取输出 → `EXTRACTOR_VERSION` 必 +1）
- **孤立短词被判成公式行**（`_is_mathish_line`）：`"in"` / `"of"` / `"as"`
  这种 2 字母残行满足「≤2 字母且 ≤12 字符」→ 判为公式行；若相邻还有 `[?]`
  行，`_mark_broken_formulas` 会把它并进 `⟦FORMULA⟧`，**正文就此消失**。
  与 §4.12「正文优先」同源的漏网。
  修法：纯 `[a-z]{1,3}` 且不含数字/括号/关系符时返回 False。
- **短双栏页直接退回 plain**（`len(words) < 40` / `len(below) < 30`）：
  两栏末页、只有图注的页会走 pdfplumber 默认顺序 → **两栏逐行交错**，
  正是 §4.5 要修的病。应改成比例判据 + 补一条 39 词的合成双栏用例。
- 两处「公式段最长行数」阈值不一致（`>10` vs `>12`），同一段 11~12 行碎片
  在两条路径上得到不同结果。

**这三条改完的代价**：所有译文快照作废重翻（用户要重新等翻译）。
→ 建议攒到一次改动里一起做，并照 §4.12 的做法跑全库 24 篇 / 391 页前后对比。

### 2.2 同步层
- `api_sync` 是 `async def` 但通篇同步 IO（写文件 / `_sha256_file` 读 MB 级
  / 可能复制 256MB PDF）。整体挪 `asyncio.to_thread` 是对的方向，但要确认
  `_write_local_progress` 等不依赖线程局部状态。
- `_sync_root()` 无缓存，每个批注请求要走 2~4 次文件系统探测（读 env →
  坚果云 `iterdir` × 3 → 解析 `UsersMap.json`）。可按 env 值做 memo，
  但 `tests/conftest.py` 会逐用例 monkeypatch，**必须按 env 值作 key**。

### 2.3 重复代码（能省 ~200 行，但都在热路径上）
- `app.py` 翻译主循环 + 漏译重译两处几乎逐行相同（~110 行）；抽
  `_translate_chunks()` 需跑 `test_translation_robustness.py` 全量回归。

- `app.py` 的 djb2/base36 与 `merge_changes.py` 各一份；`_paper_id_for` 的
  docstring 说"复用 merge_changes 的实现"但实际调用本地版本。抽公共模块
  会触及 `test_paper_id_contract.py` 的契约，需谨慎。

### 2.4 前端

### 6.2 `_is_mathish_line`：只排除「整行都是英文常用短词」

不是"有字母就不算公式"—— 公式碎片本身就长这样（`ndm gp`、`x`），
一刀切会让公式散架、碎片直接进 prompt，模型照着编（§4.6）。
改成一张**英文常用短词表**精确排除：

```
"in of as"  → 全在表里 → 正文残行 → 不是公式 ✓
"ndm gp"    → 不在表里 → 公式碎片 → 照旧       ✓
"x"         → 不在表里 → 公式碎片 → 照旧       ✓
```

**实测收益**（全库 27 篇 / 429 页逐页前后对比，工具 `microbench/_extract_diff.py`）：
散文词 `as` / `and` 不再被吞进公式标记 —— 旧版它们被并进 `⟦FORMULA⟧`，
**正文整句消失**（§4.12 同源漏网）。

### 6.3 ❌ 分栏阈值 40/30 → 12/10：**改了，又回退了**

改成 12/10 的理由当时是"原阈值没挡住任何真问题"。**这个理由是错的。**

取证：全库只有 3 页 `words < 40`，当时把 3 页都当成"一页一张图的短页"。
实际其中 1 页是
`2024_Fe_MgO_Fe_DMFT_TMR_first_princ.pdf` 第 20 页 ——
**双栏论文的最后一页，整页只有一条横跨两栏的参考文献** + 右上角页码。

降阈值后它进了分栏路径，而栏缝恰好落在连字符上（`"Ap-" | "plied"`）→
参考文献被从中间劈开、页码 "20" 楔进两半之间。
用 fitz 渲染原页确认：那条参考文献本来是**跨栏整行**。

→ **词数少 ≠ 不可能分栏**。阈值回退 40 / 30，并加测试锁死。

### 6.4 ❌ 公式段阈值 10 / 12 合并成一个：**改了，又回退了**

当时合并的理由："同样的 11~12 行碎片，一条路径判'整段作废'、另一条判'定位公式块'，
行为不一致"。**两个阈值管的是两件事**：

- `_mark_broken_formulas`（10）：这段是坏公式 → 换成 `⟦FORMULA⟧` 占位（无坐标，
  裁不出图）→ 阈值小一点更保守
- `_formula_spans`（12）：这段是一整条公式 → 定位 bbox，前端从 PDF 原页裁图
  → **阈值必须够大**

合并到 10 的后果（真实案例）：
`2024_1f_noise_TMR_sensor_bath_corre.pdf` 第 6 页的式 (A1) 整整 **11 行**
（积分上下限 + 求和号 + 分式被拆成多行）→ 定位失败 → 11 行碎片直接进 prompt
→ 模型会照着编出一条不存在的公式（§4.6：错公式比没公式危险得多）。

用 fitz 裁图比对确认：阈值 12 裁出来的是完整的式 (A1)，阈值 10 裁不出图。
→ 拆回两个常量，各自写清依据，并加 `tests/test_paper_text_formula_spans.py`。

### 6.5 `EXTRACTOR_VERSION`：**保持 5，不 +1**（附完整取证）

结论先说：**用户的 75 页已译快照全部保留，不用重翻。**

用户现存 6 份快照、75 页已译：
- 19 页的快照**没有** `extractor_version` → 按 §4.18「没有版本号也算旧」，
  本来就已经整份作废（与本次改动无关）
- **56 页 `ver=5`** → 这批才是真正在用的

抽取层改动最终影响 **429 页中的 10 页**（2.3%）。逐页比对后，
**落在 56 页已译范围内的只有 1 页**：
`2008-JAP-multiferroelectrics-review.pdf` 第 17 页。

这一页的变化是：

```
-⟦FORMULA:48.1,422.1,297.3,483.8⟧
+as
+⟦FORMULA:64.5,437.2,297.3,483.8⟧
```

fitz 裁图实证：
- 旧标记裁出来 = 完整的式 (21) **+ 左上角一个孤零零的 "as"**（散文词被吞进公式图，
  正文里同时丢了它）
- 新标记裁出来 = 干净的式 (21)，"as" 回到正文

**且该页已保存的译文核对过**：`⟦FORMULA:48.1,...⟧` 前一句是
"…的运动方程："，中文里这个 "as" 本来就不需要译（"…可定义为…"）。
译文与新抽取**仍然对得上**，不会错位。

→ 判据不是"抽取输出变没变"，而是**译文是否还对得上**。
  这一页译文仍然对得上 → 不作废。
→ 如果 +1，代价是 **56 页全部重翻**（外加本来就作废的 19 页），
  换来的只是一个英文虚词的位置变化 —— **不划算**。

> ⚠ 这次**不** +1 是**逐页取证后的特例**，不是"抽取改了也不用 +1"的通例。
> 将来任何真正改变抽取输出的改动，**仍然必须 +1**（§4.12② / §4.18）。

## 1. 页内阅读顺序：一页内由左至右

**用户诉求（2026-10-23）**："一页中就是从左到右翻译，一直都是从左到右"。

### 1.1 顺序规则

最终送进模型的页面文本，顺序必须是：

```
整宽块（页眉/标题/整宽图注）
  → 左栏正文（从上到下，整段读完）
  → 右栏正文（从上到下，整段读完）
  → 跨栏单元（整宽表格，整块保留）
```

**绝不能左右交替**（左1→右1→左2→右2）—— 译文会左右横跳。

### 1.2 关键坑：左右两栏的起始高度可能不同

`JACERS 综述第 3 页` 是典型：右栏图注从 `y=227` 就开始，左栏正文要到 `y=450` 才开始
（页顶被一张大图占住了左栏）。

旧实现把"双栏正文起点（`y_split`）以上"**整宽裁一刀当页眉**，于是右栏那半张页面
被抢到最前面，左栏正文反而排后面 —— 用户看到的正是"先翻译右边的了"。

**现在**：顶部区域也用同一套"按带找栏缝"的判据分栏（`_extract_top_region`）：
- 真的双栏的带 → 左右分开，各自归位
- 整宽的带（页眉/标题/整宽图注）→ 单独成块，仍排最前
- 只有一栏有字的带 → 归那一栏

### 1.3 改这块时必须跑

```bash
python -m pytest tests/test_column_order.py -v
```

该文件锁死了：左栏整段早于右栏整段、跨栏表格整块保留且在正文之后、
不对称双栏页（`JACERS` 第 3 页）的顺序契约。

**全库回归**（可选，改动较大时跑）：

```python
# 24 篇 250 页：0 报错，123 个双栏页分栏归属全部干净
#   （仅 8 处是公式上标碎片页，单字符无法判定栏归属，非真回退）
```

## 2. 划词答疑：为什么会有"一直转圈然后什么都没有"

### 2.1 根因

**MiniMax-M3 的思考 token 和正文共用同一个 `max_tokens` 预算池。**

实测（真实 API，17600 字上下文 + `max_tokens=4000`，即答疑面板的原始配置）：

| 模式 | 结果 |
|---|---|
| 默认（开思考） | 思考烧掉 4000 token，**正文只剩 2 个字符**（两个换行） |
| `thinking={"type":"disabled"}` | 立刻返回 **8238 字符**完整答案 |

### 2.2 修复：三处必须同时改

任一处漏掉都不生效（我在这里栽了两次）：

**a) 空正文检测按非空白字符计数**

```python
body_visible_chars += len(x.strip())   # 不能是 len(x)
```
两个换行会被当成"有内容"，守卫永远不触发。

**b) 守卫必须放在 SSE 循环 _之后_**

实测：思考烧光时上游发完 `finish_reason="length"` 就**直接断流，
根本不发 `[DONE]` 哨兵**。

守卫只写在 `if data == "[DONE]"` 分支里 → 永远触发不了。

**c) `emitted` 按非空白字符判定**

```python
if chunk.strip():
    emitted = True
```
空正文时那两个换行已经被 yield 出去了，`emitted=True` 会让
"已输出内容就别降级重试"的分支直接抛出。

### 2.3 现在的行为

正文为空 → 自动用 `thinking=disabled` 重试一次 → 用户拿到完整答案。
（同步路径 `chat()` 早就有类似机制，流式路径此前缺失。）

## 3. 表格/曲线图：截图直接给 M3（多模态）

**用户原话**："minimaxm3 是多模态模型，如果表或者图不好文字化给他的话，
完全可以截图给它，让它回答问题"。

### 3.1 为什么需要

表格和曲线图被 pdfplumber 抽出来只是碎片（`"2 4 3"` 这种上下标、坐标轴刻度），
模型看到一堆没意义的字符，自然答不上来。

### 3.2 链路

| 环节 | 位置 | 说明 |
|---|---|---|
| 渲染 | `paper_text.render_page_png()` | PyMuPDF（`fitz`），`zoom=2.0` ≈ 144 DPI，带总像素上限 |
| 采集 | `index.html` `_captureSelectionPageImage()` | 直接裁剪**已渲染好的** PDF.js 画布（划选矩形包围盒 + 外扩），不额外请求服务端 |
| 传输 | `app.py` `ExplainSelectionRequest.page_image` | base64 PNG（不含 data URL 前缀） |
| 组装 | `app.py` `explain_selection_stream` | OpenAI 兼容 content 数组：`[{"type":"text"}, {"type":"image_url"}]` |

### 3.3 约束

- 截图失败**自动降级**为纯文本答疑，不挡路（前端 `return null` + 后端只看有没有 `page_image`）
- `fitz` 本机已装，**不需要新依赖**
- 模型侧：M3 实测支持 `image_url` + `data:image/png;base64,...`（HTTP 200）

### 3.4 实测效果

问"Fig.3 曲线峰值大约在 H 等于多少 Oe、峰值多少 mV/cm-Oe"，
模型读图答出 **约 60 Oe / 约 450 mV/cm-Oe** —— 与论文 Fig.3 实际吻合。

## 4. 公式：不猜 LaTeX，直接裁论文原图

**用户原话（2026-10-24）**："公式渲染还有问题……基本没有和文中的公式一样的……
分子分母分不清谁是谁……反正这个公式就还没有参考意义"。

### 4.1 为什么不能拼 LaTeX

公式在 PDF 里是矢量排版（分子一行、分母一行、上下标各一行），文本层抽出来
是乱序碎片。照碎片拼 LaTeX 极容易把**分子分母装反** —— 而错公式比没公式
危险得多：用户会照着它去算（本项目的铁律，见 AGENTS.md §4.6）。

### 4.2 现在的做法：只记坐标，裁原图

| 环节 | 位置 | 说明 |
|---|---|---|
| 识别 | `paper_text._formula_spans()` | 连续的「数学行」且含等号 → 一个公式块 |
| 记坐标 | `paper_text._lines_to_text()` | 输出 `⟦FORMULA:x0,y0,x1,y1⟧`（PDF 页坐标，pt） |
| 穿过模型 | `app.py` 提示词第 13 条 | 要求模型**逐字照抄**标记（连坐标一起） |
| 清洗 | `translation.sanitize_translation()` | 坐标坏了（数量不对/不成比例）→ 退回文字提示 |
| 裁图 | `app.py` `GET /api/paper/formula_image` | PyMuPDF 按坐标裁 PNG，`scale=4`（≈288 DPI） |
| 显示 | `index.html` `renderFormulaImages()` | 标记 → `<img class="formula-shot-img">`，失败退回文字 |

实测（JACERS 综述第 2 页 eq (2)）：裁出来的就是论文里那个分式，
**分子 `n d₃₃ᵐ g₃₁ᵖ`、分母 `n s₁₁ᵖ(1−(k₃₁ᵖ)²) − s₃₃ᵐ(1−n)` 一模一样**。

### 4.3 判据（改动时必须一起改）

一条行被当成「数学行」的条件：

1. **词状 token < 2 个**（≥3 字母的纯字母词，`(cid:N)` 不算）
   → 正文优先：`are assumed: α = 0.05, …` 有 3 个词状 token → 是正文；
   `eeﬀ ¼ 33 33 (3)` 只有 1 个 → 是公式。
2. 含关系符号（`= ≈ ≤ ≥`，PDF 里常被抽成 `¼`）
   → **必须有等号**：表格行也含大量 `(cid:)` 碎片，但表格行没有等号 ——
   没有这一条，整张表会变成一张图，用户就没法翻译表里的内容了。
3. 块高 ≤ 90pt（超高的多半是表格）。

⚠️ **正文绝不能被吞进公式图**（实测踩过：IEEE 论文
`f(ω) = … Substituting the inverse` 整行被吞 → 译文里这句话直接消失）。
判据放宽前先跑 `tests/test_reader_formula_table.py`。

### 4.4 改这块时必须跑

```bash
python -m pytest tests/test_reader_formula_table.py -v
```

## 5. 表格：截图交给多模态模型逐格抄

**用户原话（2026-10-25）**："对于表格的话个别单元他这个都抽错的话你也给我
直接上这个多模态读图吧……我要的是这个阅读的……至少顺序要是很正常的"。

### 5.1 为什么表格不能交给文本模型

表格在 PDF 文本层是碎的：

```
d (pC/N) (cid:4)90 (cid:4)175 (cid:4)109 B700 16.5
```

连负号都认不出（`(cid:4)` 就是 `−`）。文本模型只能靠上下文猜对齐，
结果是**整行数值错位**：实测 JACERS Table I，d31 行的 `16.5` 跑到了 d33 行、
`7200` 变成 `B700`。

### 5.2 现在的链路

| 环节 | 位置 | 说明 |
|---|---|---|
| 识别 | `paper_text._find_table_regions()` | 按**「表状行成段」**（词短 + 含数字 + 没有像英文单词的东西） |
| 记坐标 | `paper_text._table_marker()` | 输出 `⟦TABLE:x0,y0,x1,y1⟧`（PDF 页坐标，pt） |
| 裁图 | `app.py` `_pdf_clip_png()` | PyMuPDF 裁 PNG，`scale=4`（≈288 DPI），带 4M 像素上限 |
| 抄表 | `app.py` `_read_table_vision()` | 多模态模型逐格抄 → Markdown（跟着用户选的模型走） |
| 拼接 | `app.py` `_prepare_tables()` | 标记换成中性的 `⟦TABLE_n⟧`，翻译后按位置拼回（前后补空行） |
| 渲染 | `index.html` `formatMarkdownLite()` | Markdown 表格 → `<table class="md-table">` |

### 5.3 判据的坑

- **不能用"有很多数字"判表格**：公式行也全是数字（`a ¼ 33 31 (2)`），
  按数字判会把公式当表格（实测 eq (2)/(3) 被误判成两张表）。
  → 表格区域按**「表状行成段」**认：词短 + 含数字 + **没有像英文单词的
  东西**。判"像英文单词"不看字母数（材料名 BaTiO3 也是长词），看**是否以
  小写为主**。
- **表格区域只能由表状行延续**：表题后面跟一段"短"正文时，区域会一直延伸，
  把那几段正文从正文里删掉，还当成表格让多模态"逐格抄" —— 正文就这么消失
  了（独立审查在 13 处发现过）。表题本身**留在正文里**由主模型翻译。
- **页尾截尾会切坏标记**：标记里是小数点，而截尾按"最后一个句末标点"切
  → `⟦TABLE:28.2,639.4,536.3,754.1⟧` 被切成 `…754.`，半截匹配不上，
  那张表就整张丢了。
  → `_trim_page_tail()` 的切点必须避开标记内部，标记自己的 `⟧` 才是合法切点。
- **裁剪框越界会抛异常**：`pdfplumber.crop()` 的框超出页面 → ValueError。
  为避开切字而外扩 margin 时很容易把框推出页面下沿 → 整组文字全丢
  （实测 24/391 页中招）→ 裁剪框四边都要 clamp 到页面内。
- **静默的 `except Exception: return []` 会把整页正文丢失藏起来** →
  兜底必须留痕（打堆栈到 stderr）。
- **缓存查询必须在读图之前**：表格读图每张 10~30 秒，放在缓存查询之前的话，
  缓存命中也要先花这个时间 → 含表格的页等于缓存完全失效。
- 主模型偶尔会把 `⟦TABLE_n⟧` 标记弄丢 → 服务端兜底：漏掉的表格追加到译文末尾。

### 5.4 实测效果

JACERS 综述第 2 页 Table I：文本层抽出来是 `B700 16.5`、
`d (pC/N) (cid:4)90 (cid:4)175 (cid:4)109`；多模态抄出来是
`−90 | −175 | −109 | | ∼700 | 16.5` —— **和论文里印的一模一样**，
连论文自己把 2605 排进表头的排版毛病都照抄了。

## 6. 解不出的数学符号：裁图认字（2026-10-25）

**用户反馈**："只要涉及 × 的，它都显示的是个？"

**根因**：TeX 数学字体（`MathematicalPi-Three` / `CMEX10` / `AdvP4C4E74` /
`LCIRCLEW10` …）在 PDF 里**没有完整 ToUnicode 映射** → pdfplumber 吐 `(cid:3)`
→ 抽取层换成 `[?]`（故意的：防止模型把 cid 猜成 `\\approx` / `\\times` 编造公式）。

**但字形是画出来的** → 裁图让多模态认字。

### 5.1 抽取层契约

- **孤立**的解不出符号 → `⟦G:<下标>⟧`（下标 = 该字形在"本页未解出字符表"里的位置）
- **连续一整串**（公式碎片 / 引用编号 `[12]`）→ 整体一个 `[?]`（旧行为不变）
- 未解出字符表按 `page.chars` 的内容流顺序排（与 `page.chars` 顺序一致，可复现）
- 行匹配判据：字形落在**行的垂直带内** + x 区间在行内（**不能按 top 比**，
  数学公式的上下标高度差很多）
- `plain` 兜底路径（分栏失败时）也走行级抽取 —— 否则没有行级几何可用

### 5.2 服务端契约（2026-10-25 修订）

1. **整篇一次**解析（`resolve_document_glyphs`）—— ⚠️ **不能逐页调**
   - 旧实现逐页调认字 → 36 页的论文发 **35 次串行**多模态请求
     （实测 29~48s/次 → 8 分钟以上，用户看到的就是"半天没反应"）
   - 整篇做：先全局按**语义键**去重 → 全篇通常 1~3 次批量调用
2. 裁出字形 → **语义键** = `字体基名|字符码`（去掉 `XXXXXX+` 子集前缀）
   - 这是词典的**主键**：跨论文、跨设备稳定
   - 实测：全库 24 篇 / 6184 个字形实例 → 只有 **101** 个不同语义键，
     其中 76 个跨 ≥2 篇重复 → 认一次就长期命中
3. 词典（`logs/glyph_dict.json`，坚果云同步、两台设备共用）命中 → 直接用
   （**零模型调用**，这就是"打开一篇论文 3 秒"的原因）
4. 未命中 → 拼成小图 → 多模态认 → **白名单校验** → 存词典
5. 认不出来 → `[?]`（**绝不猜**）
6. **回填必须在 finally 里** —— 打开 PDF 失败 / 渲染失败 / 认字抛异常 等
   任何路径，⟦G:n⟧ 都**不能**外泄进 prompt（模型会照抄或瞎编，§4.6 红线）
7. **时间预算**（`GLYPH_RESOLVE_BUDGET_SEC`）→ 超时退回 `[?]`，绝不无限等

**必须关思考**（主模型是推理型，思考会吃光 token 预算，实测输出被截断 0 字符）。

### 5.2.1 ⚠️ 形状指纹**不能**当主键（实测踩坑）

旧实现用"16×16 拉伸位图 + 汉明距离"当词典主键。**全库实测证明它不可靠**：

| | 同符号不同实例 | 异符号之间 |
|---|---|---|
| 拉伸 16×16（旧） | 组内差 中位 **61** | 组间差 中位 **74** |

→ 两者**重叠** → 阈值 40 既命不中，又会把 ≈ 认成 ≥（异符号误判率 **26~41%**）

更糟的是：用它做"旧词典 → 语义键"的迁移时，**20 个不同语义键全被映射成 `÷`**
（肉眼核对发现 `MathematicalPi-Three|16` 明明是 `)`）。→ **旧形状词典本身是污染的，
不能拿它推语义键**；语义键的符号只能由模型直接认。

形状指纹**降级为二级校验**（`_shape_bits_stable`，等比补白版）：
- 同语义键·跨文档形状差 中位 **0** / p75 2 → 极稳定
- 但异语义键之间也近（中位 47）→ 区分不开，所以只能当"极端不像就拒绝"的兜底
- 阈值 `_SHAPE_GUARD_MAX_DIFF = 96`（同键实测最大差 81 → 放宽到不误杀同符号）

### 5.3 改这块时必须跑

```bash
python -m pytest tests/test_reader_glyphs.py tests/test_glyph_perf_regression.py -q
```

> ⚠️ 新增的 `test_glyph_perf_regression.py` 里有一条**端点级**护栏：
> 把接口改回逐页调用，它必须变红。写这类护栏时注意**别让它假绿** ——
> 最小 PDF 里没有解不出的符号时，逐页循环压根不会进 → 断言恒真。

## 7. 表格渲染：Markdown 表格必须渲染成真正的 `<table>`

- 护栏：`microbench/_test_reader_markdown.js`（node 跑真实前端代码）

## 8. 翻译快照必须带「抽取算法版本号」

**踩坑（2026-10-24）**：10-23 14:17 存的快照被 10-23 16:36 的栏序修复甩在
后面 → 读者照旧恢复旧快照 → 用户看到的还是"先翻译右边那栏"，
**还以为修复没生效**（其实代码早就修好了）。

- `paper_text.EXTRACTOR_VERSION`：改了「页内顺序 / 公式 / 表格抽取」就 +1
- 快照保存时由服务端盖上 `extractor_version`
- 加载时（`GET /api/pdf/snapshot/load`）版本对不上 → **整份作废**，
  返回空页列表 → 阅读器照常把没翻的页重翻一遍
- 前端会弹一条提示："♻️ 旧版译文已失效（抽取算法已升级…），正在重新翻译"

## 9. 批注（标注）：记录不丢 + 列表按当前页定位

**用户原话（2026-10-25）**："如果我重新翻译的话……这个标注是不是就直接没了？
这个记录要有。还有就是如果有很多标注的话……我希望就是我点开哪一页，
它显示的那个标记的列表是从那个开始的，不要每次都从第一页的标注开始。"

### 8.1 两条承诺

| 承诺 | 实现 | 判定 |
|---|---|---|
| **重译后记录不丢** | 译文侧标注找不到原引文时**不删除**，只置 `orphan=true` | `applyAnnotationsToPage()`：包不上高亮 → `a.orphan = !(a.rects && a.rects.length)` |
| **列表按当前页定位** | 抽屉打开时滚到**当前页**的第一条 | `openAnnoDrawer()`：按 `el.dataset.page` 找本页条目 |

### 8.2 "位置失效" ≠ "批注丢了"

重译会改写译文 → 原来划的那句话在新译文里不存在了 → 高亮包不上。

- **译文侧标注**（无 `rects`）：高亮找不到了 → 标 **⚠ 位置失效**（虚线边框），
  但 `quote` / `note` / 颜色全部保留，笔记一个字都不丢
- **PDF 侧标注**（有 `rects`）：高亮画在 PDF 画布的覆盖层上，**不受重译影响**
  → 永远不算失效
- 失效标记**会自愈**：译文恢复成原来那句 → 重新包上高亮 → `orphan=false`

### 8.3 抽屉定位规则

列表按页码排序后：

1. 本页有标注 → 滚到**本页第一条**（`block: "start"`）
2. 本页没有 → 落在**下一页的第一条**
3. 超出范围 → 回退到第一条

### 8.4 选区归属：不能只看鼠标松开的位置

**踩坑（2026-10-25 浏览器实测）**：在译文里拖选一整行，**把鼠标松在行尾的留白上**
（这是很自然的动作）→ `mouseup` 的 `e.target` 不是文字元素
（可能是 `.page-text` 或面板留白）→ 判定链全部落空 → `source="general"`、
`pageNum=null` → 批注被存成 **page=0（章节视图）**。

后果：用户在**正在看的那一页**上根本找不到这条批注（它躺在章节视图里），
PDF 侧同理 → `rects` 收不到 → 原文高亮也没了。

**修法**：`_resolveSelectionOrigin(targetEl, range, activeSection)`
—— 先按 `e.target` 判断，**判不出来就用选区 `range.commonAncestorContainer` 兜底**。
DOM 里是元素就用元素本身，是文本节点就取 `parentElement`。

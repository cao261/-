所以桌面端的 `app.py` / `llm.py` 修复**完全不会**自动到平板。

上游 `2216afa` 只在平板改了 `SYS_RESEARCH` 一个提示词（+14 行）。
另外三个根因在平板端**原样还在**：

| # | 桌面端修的 | 平板端当时的现状 | 本轮 |
|---|---|---|---|
| ① | 思考预算按「思考+正文」算（§4.38） | 答疑 `max_tokens: 8000` → **正文 0 字** | ✅ 16000 |
| ② | 空正文自动加预算重试（§4.38 连带） | 只弹一句「换个模型或调大 max_tokens」→ 用户什么都没等到 | ✅ 自动重试 |
| ③ | 重答不死锁 + 请求序号守卫（§4.37） | 无守卫 → 旧请求收尾会把**新请求的停止按钮**藏掉 | ✅ 序号守卫 |

| ⑤ | 能力边界写进三个提示词（§4.37） | 只有 `SYS_RESEARCH` 有；`summarize` 没有 | ✅ 补齐 |

## 2. 平板端这轮改了什么（`microbench/static/tablet/app.js`）

### ① 思考预算（§4.38）

```js
const AI_QA_MAX_TOKENS = 16000;        // 答疑：思考+正文 共用预算池
const AI_TRANSLATE_MAX_TOKENS = 4000;  // 翻译：关思考的直译型，按正文算
const AI_MAX_ESCALATION_MAX_TOKENS = 32000;  // 抬预算重试的上限
const AI_QA_TIMEOUT_MS = 300000;       // 300s，与电脑端 QA_TIMEOUT 一致
```

> **⚠ 别照抄数字**：同一个常量在不同任务里含义不同 ——
> 翻译是「关思考的直译型模型」（4000 按正文算），
> 答疑是「思考型模型」（必须按思考+正文算）。
> 抄错就复现「想 43 秒然后交白卷」。

**翻译用强制思考模型时自动抬到 16000** —— 平板的翻译模型是用户自己配的，
不能假设他一定配了 M3。

### ② 空正文自动重试

原来只提示不重试。现在：

- **能关思考**的模型 → 关掉思考 + 抬预算，重试一次
- **强制思考**的模型（M3.1-Flash）→ 只抬预算，重试一次
  （⚠ 「关思考」对它是**空操作**：参数根本不下发 → 请求与第一次完全相同 →
  再等 55 秒还是 0 字。电脑端实测 55s → 111s 才报错。）
- 上限 32000，不无限抬。

### ③ 请求序号守卫

```js
const mySeq = ++aiRequestSeq;
const isCurrent = () => mySeq === aiRequestSeq;
// ...
if (isCurrent()) { /* 只有当前请求能碰停止按钮 / 多轮上下文 */ }
```

没有它：**新请求替换旧请求后，旧请求的回调仍会执行** → 旧请求收尾时
把新请求正在用的停止按钮藏掉（用户没法停止新请求了），
还会把旧答案塞进多轮上下文。

**顺带修了一个隐患**：`aiRequest()` 原来读**全局** `aiAbort.signal`，
而全局变量会被下一次请求换掉 → 旧请求的响应会被当成新请求的结果。
现在 signal **由调用方传入**。

### ④ 思考强度 `reasoning_effort`

```js
const AI_REASONING_EFFORT = "low";
```

**⚠ 平板这里跟电脑端有一处**故意的**差别** —— 判定只看**网关地址（base）**，
不看模型名：

> 平板的用户可以把自己的接口指向**任意** OpenAI 兼容网关，
> 那种网关上照样挂着「MiniMax-M3.1-Flash」这个模型名，
> 但它**不一定认 `reasoning_effort`** → 发了就 **HTTP 400**（请求直接被拒）。
> → **网关才是决定「认不认这个参数」的东西，模型名不是。**

强制思考模型拿 `none` 会 400 → 自动降级成 `low`。

### ⑤ 摘要提示词补能力边界

`SYS_SUMMARY`（摘要用）与 `SYS_RESEARCH` 的能力边界条款**逐字一致** ——
护栏会断言两者相同，防止改了一处忘了另一处。

## 4. 桌面端要不要跟着改？

**这轮不用。** 桌面端 `app.py` / `llm.py` 已经是修好的状态（`2216afa`）。
但有两点**值得抄进桌面端的判断习惯**：

1. **`reasoning_effort` 的判定依据**：`llm.py` 现在是 `base + 模型名` 一起判。
   桌面端只有**自己配的**自定义模型才可能踩坑（用户填个自建网关 +
   模型名叫 MiniMax-M3.1-Flash → 400）。**目前没接到用户投诉，先不动**
   （改了要同步 `tests/test_llm_thinking_params.py` 的断言）。
2. **平板端的「译文快照版本闸门」**：本轮只改了 AI 面板，
   **没有动 `paper_text.EXTRACTOR_VERSION`** → 旧译文**不作废**，不用重翻。

## 5. 验收（对方设备照着跑）

```powershell
# 1) 拉代码
git pull --rebase origin main

# 2) 全量测试（平板的 node 套件会自动被 pytest 跑一遍）
python -m pytest tests -q -m "not slow"

# 3) 重打 APK（平板的交付物只能由构建脚本产出）
pwsh android/build_apk.ps1

# 4) 装到平板上人工过一遍
#    - 划词问一句需要推理的问题 → 4~6 秒出正文（不是干等一分钟）
#    - 问"帮我上网找张实物图" → **先给实质内容**，最后一句才说没有联网能力
#    - 连续问两个问题 → 第二个能发出去，停止按钮不消失
#    - 翻译一段话 → 译文完整、干净（没有思考文本混进来）
```

> ⚠ **手动 `git pull` 之后 APK 不会自动重打**（AGENTS.md §4.19）。
> 平板端要拿到新版 APK，得在**平板侧那台设备**跑 `build_apk.ps1`，
> 或者等平板侧 agent 推上来（本轮已经推了）。

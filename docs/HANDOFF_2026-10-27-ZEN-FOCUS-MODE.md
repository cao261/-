## 1. 专注模式怎么用

### 进入 / 退出

| 动作 | 结果 |
|---|---|
| 顶栏「◱ 专注」按钮 | 进入专注（**这个按钮一直可见**，不会把自己关在门外） |
| 快捷键 `Z` | 进出专注（**输入框里不生效** —— 打字不会误触发） |
| 快捷键 `Esc` | **先收工具条，再按才退出专注**（分级退出，不会一把全关） |
| 顶栏「✕ 退出专注」 | 直接退出 |

### 唤出工具条（默认是收起的）

四种方式，任何一种能用就行：

1. **顶部那条 7px 细把手** —— 点一下展开
   （**展开后不能再点把手收起**：这时把手被顶栏盖住、点不到；
   收起靠 `Esc` / 鼠标移出顶栏 1.2s / 顶栏「✕ 退出专注」）
2. **鼠标移到屏幕最上方 40px** —— 自动滑出（停手 2.6s 自动收起）
3. **内容区往回上滑 / 滑到最底部** —— 自动滑出
4. 点顶部把手后工具条**常驻**（指针停在上面不自动收起，离开后 1.2s 收起）

### 收起了什么

- **章节导航**（`.reader-nav`）→ 顶栏「章节」按钮开
- **AI 提问区**（`.reader-aux`）→ 顶栏「提问」按钮开
- **划词答疑悬浮钮**（`#reader-qa-floating-btn`）→ 默认藏
- **顶栏工具条**（`.reader-topbar`）→ 滑出

> **划词气泡（`#reader-selection-bubble`）不藏** —— 它是临时出现的，
> 划词答疑是核心工作流。

### 单栏 / 双栏

- 顶栏「单栏 / 双栏」按钮切换（**小屏用单栏更宽**）
- 单栏下多一个「论文 ⇄ 译文」按钮：论文页和译文页**互斥**切换
- 单栏**默认显示译文页**（小屏先看译文，想看原文再切）

### 偏好会记住

「上次开着」→ 下次打开论文**直接进专注**，不用再点一次。
（存在 localStorage `microbench_state_v1` 的 `zenPref`。）

## 2. 浏览器实测抓到的 4 个真 bug

> 这 4 个都是**看截图 + 埋探针**抓出来的，读代码看不出来。
> 前面还走过一次弯路：**以为修好了，其实没修好** —— 详见 §3.4。

### Bug 1（高）：单栏看论文页，右半屏全空

**根因**（探针实测 `getComputedStyle` + `clientWidth`）：

    .reader-shell  cw=616   ← 视口 1280px，它只占一半
    .pdf-split     gtc="308px 308px"

`#reader-modal` 打开时是 `display:flex`（**行向** flex），
`.reader-shell` 是它的 flex item，`width:auto` → 走 **fit-content 收缩**：
壳的宽度 = 内容的 max-content，**不是视口宽度**。

平时看不出问题 —— 顶栏在文档流里、内容很宽 → 壳被撑满。
**一旦顶栏脱离文档流**（专注模式把顶栏改成 `position:fixed`），
壳里只剩 `.pdf-split` → 壳立刻缩成 fit-content → 半屏。

**修**：`.reader-shell { width:100%; min-width:0 }`。

### Bug 2（高）：画布永远停在 520px（兜底宽度）

**根因**：阅读器打开前是 `display:none` → `#pdf-pages-list` 的 clientWidth = 0
→ 首次渲染走 `availWidth = max(260, (listEl.clientWidth || 520) - 4)` 的**兜底 520**。
等阅读器**真的显示出来**，**窗口尺寸一点没变** → `window resize` **根本不触发**
→ 画布永远 520px。

**修**（三处一起，缺一不可）：

1. `ResizeObserver` **直接观察 `#pdf-pages-list`**
   —— 覆盖「隐藏→可见」「单栏→双栏」这些 window resize 抓不到的宽度变化；
2. `_pdfRelayoutBusy` **忙标记** —— 重绘期间忽略尺寸回调，
   否则「清空列表 → 高度变化 → 又排一次重绘」会**自激循环**；
3. 渲染结束后用**渲染起始宽度**（`renderW0`）复核一次 ——
   阅读器可能是在渲染**过程中**才变可见的，那一瞬间的观察器回调被忙标记挡掉了。

### Bug 3（中）：切到「论文页」一片空白

**根因**：`#reader-modal.zen.zen-single #pdf-viewer-container { display:none }`
**无条件生效** → 切到论文页时 PDF 容器仍被藏。
章节视图那两栏同理：两条规则叠加 → **两栏全被藏**。

**修**：
- PDF 侧改成 `#reader-modal.zen.zen-single:not(.zen-show-orig) #pdf-viewer-container`
- 章节视图侧改成 5 条明确互斥的规则，
  并显式把 show-orig 下的原文 pane `display:block` 放回来。

### Bug 4（中）：「章节」「提问」点了像坏了

**根因**：章节导航（`.reader-nav`）和 AI 提问区（`.reader-aux`）
都住在「章节视图」容器 `#reader-body` 里，而 PDF 双栏模式下**那个容器整体 `display:none`**
→ 点这两个按钮**什么也不会发生**。

**修**：
- 点「章节」/「提问」→ **先切到章节视图**，再展开对应面板（并弹提示说明为什么换了视图）；
- 但章节视图的**内容**来自「全文拆分章节」（`_readerState.sections`），
  只有走过 `openVaultPdf` / 拉取全文 的论文才有；
  **仅靠地址栏恢复的本地 PDF 没有章节数据** → 这种情况**如实提示**
  （「这篇还没有章节数据 —— 需要先『拉取全文』拆分章节」），**不给用户一片空白**。

## 3. 设计决策与踩过的弯路

### 3.1 工具条复用既有 `.reader-topbar`

不另做一套按钮 → 既有功能（缩放、全篇重译、模型下拉、快照、同步、主题…）**一行不少**，
也不会和顶栏分叉出两套行为。

### 3.2 顶栏用 `position:fixed` + `translateY`，**不是** `display:none`

`display:none` 就再也滑不回来了。滑出那一档 `translateY(0)`。

### 3.3 **不给 `.reader-shell` 加 `position:relative`**

那会把里面 `position:absolute` 的浮层（批注编辑器 / 笔记抽屉）的
**包含块**从 `.reader-modal` 换成 `.reader-shell` → 位置全乱。

### 3.4 走过的弯路（值得记）

**症状**：单栏看论文页，PDF 只占左半屏。
**第一次修法**：以为是基础样式里
`@media (min-width:700px) and (max-width:1100px) { .reader-shell > * { max-width:860px; margin-left:auto; margin-right:auto } }`
在交叉轴上用 `margin:auto` 取消了 flex 的 stretch → 取消掉了 `max-width` 并加了
`#reader-modal.zen .reader-shell > * { max-width:none; margin-left:0; margin-right:0 }`。

**结果：症状一点没变。**

**为什么**：本机视口是 **1280px**，那条 media query 的上界是 **1100px** ——
**它根本不生效**。真正的根因是 fit-content 收缩（Bug 1）。

> **教训**：**别按屏幕宽度猜哪条规则在起作用**。
> 正确做法是**埋探针量实际宽度**（`getComputedStyle` + `clientWidth`），一测就分清了。
> 这次要是继续在 CSS 里猜，能猜一整天。

### 3.5 `.zen-handle` 放在 `.reader-shell` 的**最后**

`.reader-shell` 是 flex column，子元素顺序是**位置型契约**：
child1 = `.reader-topbar`、child2 = `#reader-body`（章节视图）、
child3 = `#reader-pdf-view`（PDF 视图）。
把手插在前面会挤偏这个契约（README 里明确写过 JS 曾因此定位错目标）。

### 3.6 选择器一律 `#reader-modal` 前缀

靠 id 权重压住基础样式里的 `@media (max-width:1200px) .reader-body` 两列规则。

## 4. 顺带修的（不属于专注模式，但同一轮抓到的）

| # | 问题 | 根因 | 修法 |
|---|---|---|---|
| 1 | **公式符号重复**（`(H)`→`(HH)`→`(HHH)`、`αMEαME`） | KaTeX 懒加载时首屏**并发**多次 `renderMathIn` → 同一占位符渲染两遍 | 渲染前 `if (el.querySelector(".katex")) return;`（幂等守卫，display 与 inline 两处都加） |
| 2 | 底部多一条**横向滚动条** | 画布渲染时容器还没出现滚动条（宽度按"无滚动条"量），画布一加进去、竖向滚动条冒出来 → 容器少 15px → 画布比容器宽 | `.pdf-split-pane { scrollbar-gutter: stable }`（滚动条位置提前占好，宽度从一开始就稳定） |

> 公式重复那个是**既有潜在 bug**，被专注模式的额外重绘触发了 —— 一次渲染两遍。

## 4.5 独立审查揪出的 9 个问题（全部已修）

审查由 verifier 子代理**只读**完成（2026-10-27）。结论是
「代码本身没找到可证明的阻断性运行时缺陷，**但护栏对本次最核心的修复零覆盖**」。
下面是它抓到的、本轮**全部修掉**的问题：

| # | 严重度 | 问题 | 修法 |
|---|---|---|---|
| 1 | 🔴 高 | **护栏对 PDF 重绘链零覆盖** —— node 切片只切了专注模式块，重绘链被桩替换；pytest 只有 3 次字符串 grep。审查用 3 个变异体（删 `!force` 短路 / 删忙标记守卫 / 删渲染后宽度复核）证明**两套护栏全绿** | node 切片扩到 `loadPdfDocument` 之前 → **重绘链是真代码在跑**；补 5 个「被调方」变异（现在 11/11 全被抓） |
| 2 | 🟠 中 | `.zen-handle`「再点一下收起」是**死分支** —— 工具条打开时把手 `pointer-events:none` 且被顶栏盖住 → 点不到，那条分支永不可达（而注释和文档都这么写） | 删掉死分支，把把手改成**只负责展开**；注释与本文档同步改 |
| 3 | 🟠 中 | **Esc 一次按键干两件事** —— 快照/诊断弹窗自己的 keydown 没有 `stopPropagation`，专注的 Esc 会同时退出专注 + 关弹窗 | 新增 `_zenOverlayOpen()`，上层弹窗开着时 Esc **让路** |
| 4 | 🟠 中 | 章节视图**没有章节数据**时点「章节」→ 开出一条 200px 的**空列**（用户看着像坏了） | 「已经是章节视图」那一支也查 `_zenHasSections()`，无数据就如实提示 |
| 5 | 🟡 低 | `_zenScrollT` 被 4 个滚动容器共用 → 在译文栏滚 300px 再到 PDF 栏往上滚 5px，被误判成"大幅往回上滑"→ 工具条凭空滑出 | 滚动位置**按容器**分别记（`_zenScrollEl`） |
| 6 | 🟡 低 | `showToast(msg, isError, duration)` 的第三个参数是**死的**（函数只有两个形参） | 给 `showToast` 补 `duration` 形参（顺带让既有 3 处调用也按预期生效） |
| 7 | 🟡 低 | `_pdfRelayoutBusy` 是布尔不是计数 → 并发渲染时先结束的那次会把标记清掉，保护提前失效 | 改成**计数**（`++` / `--`） |
| 8 | 🟡 低 | `mouseover` 清定时器 与 `mousemove` 重设定时器 打架 → 光标停在条上抖 1px，2.6s 后工具条在光标底下自己关掉 | mousemove 里判"是否已经在工具条内"，在条内就不重置定时器 |
| 9 | 🟡 低 | `nearBottom` 对**根本不可滚动**的容器恒为真 → 一滚就弹工具条 | 前置 `scrollHeight > clientHeight + 4` |

另外还顺手改掉了一个审查点名的**成本问题**：
进出专注原本会 `force` 全量重绘（每页一次 `await renderPdfPage`），
**391 页的论文每点一次「专注」就全量重绘一遍**。
但进出专注**根本不改变 PDF 栏宽**（`.reader-shell` 恒为 100% 宽，§4.48）→
现在 `force` 只给「切单栏 / 切论文页」用（那两个确实改变栏宽），
其余交给 `ResizeObserver` 按实际宽度差决定。
浏览器实测确认：进出专注前后画布宽度**一模一样（573px）**，没有重绘。

> **教训（比 bug 本身更值钱）**：
> 第一版护栏的 7 个变异**全都只改"调用方"**（类名字符串、传参），
> 一个都没碰"被调方"（重绘链的函数体、忙标记守卫、宽度复核）——
> 于是「变异捕获 7/7」给出了一种**虚假的覆盖感**：
> 最该被守的 4 处代码，恰好是唯一没有变异体的 4 处。
> → **变异必须改被测逻辑本身**，光改调用方等于没测。

## 5. 护栏

| 文件 | 类型 | 条数 | 说明 |
|---|---|---|---|
| `microbench/_test_zen_mode.js` | 行为级 | **32 条 + 变异自检 11/11** | node 从 index.html 里**切出真实源码**（专注模式块 **+ PDF 重绘链**）+ 最小 DOM 桩 eval —— 测的是真代码，不是抄一份 |
| `tests/test_zen_mode.py` | 源码级 | **23 条** | 结构契约（含「CSS 选择器必须真的匹配到元素」反向检查） |
| `tests/test_reader_formula_table.py` | 源码级 | +1 条 | KaTeX 幂等守卫 |

### 变异自检是干什么的

把源码**改坏**（改类名 / 去掉清理 / 去掉 force / 去掉忙标记守卫 / 去掉渲染后复核…）
后重跑同一套断言，必须**出现失败**。
否则那套断言就是**恒真的、等于没写**。

    node microbench/_test_zen_mode.js
    # PASS 32  FAIL 0  (变异捕获 11/11)

⚠️ **变异要改「被调方」**（见 §4.5 最后的教训）：
现在 11 个变异里有 5 个是改**重绘链函数体本身**的 ——
删 `!force` 短路、删忙标记守卫、删渲染后宽度复核、把 40px 阈值改成 0、
把切单栏的 force 去掉。

### 「CSS 选择器必须真的匹配元素」这条为什么有

**血泪**：原来写的是 `#reader-modal.zen .reader-qa-floating-btn`，
可那个按钮身上的类叫 `.reader-floating-copilot-btn`
（`reader-qa-floating-btn` 是它的 **id**）→ 规则匹配不到任何元素，
**静默失效**：代码看着对、页面上按钮还在、
而且「源码里有这条规则」这种断言照样绿。

→ 现在反向验证：把 CSS 里用到的每个类 / id 拿去 HTML 里找，找不到就是死选择器。
动态类（JS 用 `classList` 切出来的）从 JS 里现算，不用手写白名单。

## 6. 平板端要不要抄

**不用**（至少这轮不用）。理由：

- 平板端是**另一份独立前端** `microbench/static/tablet/app.js`，
  桌面的 CSS/JS **一行都不过去**；
- 平板是触屏，没有"鼠标移到屏幕顶部唤出工具条"这回事；
- 平板的屏幕小是**物理限制**，专注模式解决的是"桌面窗口小 / 内容太多"。

**但如果用户明天说平板也要**：平板端要**自己**做一遍，
而且要按触屏交互重设计（不是把桌面的搬过去）。

## 7. 还没做的 / 已知限制

1. **单栏 100% 缩放时 PDF 页面会很大**（1228px 宽）——
   符合"小屏多看字"的目标，但想看整页得自己点「−」或「适配」。
2. **章节视图 + 单栏** 时，章节导航会占一整行（grid 单列 3 行布局）——
   能用，但不够精致。
3. **地址栏恢复的本地 PDF 没有章节数据** → 「章节」按钮会提示而不是空白页。
4. **没有做专注模式的"记住每篇论文的偏好"**（只记了全局的开关）。
5. 专注模式**没有平板版**（见 §6）。
6. **审查点名要人工补的一次实测：平板 700–1100px 的版式**。
   `.reader-shell { width:100% }` 是**全局改动**（非专注模式也生效）：
   审查按 flex 规格推算，**700–1100px** 段阅读栏会从"左对齐"变成"居中"
   （平板的设计意图本来就是 860px 居中，所以看起来是修好了，
   但这是**用户没要求的全局版式变更**，没有测试、没有 iPad 实测）。
   → 谁在 iPad 上用 MicroBench，**顺手看一眼**阅读栏的位置对不对。
7. 顶栏收起后仍在 Tab 键序里（`translateY` 只是位移）——
   纯键盘用户会 Tab 进看不见的按钮。没修（改 `visibility` 会打断滑出动画）。

## 2. 阻断级（6 条）

### B1　`app.py` 缺模块级 `import sys` → 漏译重译直接 500，且**重复扣费**

模型漏译 → 服务端走「重译一次」分支 → `sys.stderr` 抛 `NameError` →
HTTP 500。**已付费的译文既没返回、也没进缓存** → 下次点开同一页重新再付一次。
`find_untranslated_runs` 只要求「连续 8 个英文单词」，中文译文里保留英文摘要
就会命中 —— 不是边缘情况。

修法：顶部加 `import sys`（一处修好三处）。
护栏：`tests/test_sync_regressions_2026_10_25.py::test_app_module_has_sys`。

### B2　批注删除被同步「复活」，还回灌给删除方

A 删掉批注 → B 点一次同步 → 批注回到共享目录 → A 再打开，批注也回来了。

**根因**：同步 push 里有一段「兼容旧版本」分支，把本机
`logs/_pdf_snapshots/annotations/` 下的**陈旧副本**读回来，
用 `_merge_annotation_lists(cur, new, [])`（**deleted 传空**）合并写回共享目录 ——
已删除的 id 因为不在 `cur` 里，被当成「新增」重新加回。
删除墓碑只存在于保存请求的瞬时参数里，**从不落盘**。

修法：**删掉那段回灌分支**（批注早已是「写入即同步」，真源是共享目录）；
本机副本改成**共享目录的镜像**（拉取时照抄，不再按 id 合并 ——
合并正是把已删页加回来的元凶）。

护栏：`test_deleted_annotation_is_not_resurrected_by_sync`（连同步两次都不许复活）。

### B3　译文快照**整份替换** → 对方已翻的页被清空

前端只上传**自己翻过的那几页**，服务端却整份覆盖。
A 翻了 1–5 页、B 翻了 6–10 页 → B 同步一次，A 的 1–5 页没了 →
**A 要重翻 5 页，重新烧 token**。

（`docs/SYNC_CONTRACT.md` 声称快照是「整份替换」且「不会互相踩坏」——
 实测不成立，它是整个同步层里唯一会互相踩坏的一路。）

修法：快照保存 + 同步 push/pull **全部改成按 `page_num` 合并**；
原文变了（`paper_text_signature` 不同）时旧译文作废。

护栏：`test_snapshot_save_merges_pages`、`test_snapshot_merge_drops_stale_pages_when_source_changed`。

### B4　`merge_changes.safe_target` 穿透 junction → 平板变更包**一条都合不回来**

`resolve()` 会穿透 junction，把 `vault/01_Literature/x.md` 解析成
坚果云里的真实路径 → 相对 `vault.resolve()`（D 盘）自然「越界」→ 全部拒绝。
**当前这台机器的 vault 整体搬进了坚果云，8 个顶层目录全是 junction** ——
也就是说这个功能在当前部署下是**完全废的**。

（同一个坑 `generator._safe_path` 早就修过，改用 `os.path.abspath`；
 `merge_changes.safe_target` 当时漏了。）

修法：照抄 `_safe_path` 的写法，用**逻辑路径**做包含性判断。
护栏：`test_safe_target_survives_junction_vault`（真建一个 junction 测）+ 静态护栏。

### B5　Markdown 插值未转义 → XSS（4 条向量实测命中）

```markdown
![x" onerror="alert(1)](a.png)   →   <img alt="x" onerror="alert(1)" src="a.png">
```

笔记正文、云盘同步下来的 .md、导入的 vault 包都能走到这里。
平板的 IndexedDB 里存着 AI API Key，脚本可以读走。

**真正的根因比审计报告说的还严重**：`esc()` 的引号转义**从上线起就是错的** ——
```js
.replace(/"/g, E_QUOT + "quot;")   // ← 应该是 E_AMP
```
产出的是 `"quot;` 而不是 `&quot;` ⇒ **引号压根没被转义**，
任何属性值里的引号都能闭合属性。
（`E_AMP` 是 `&`，`E_QUOT` 是 `"` —— 抄错了一个常量。）

修法三件套：
1. `esc()` 的引号转义改回 `E_AMP`；
2. `sanitizeHtml` 改成**属性白名单**（只留 class/id/href/src/alt/… ，
   `style` 和一切 `on*` 直接丢掉）—— 比逐个禁 `on*` 稳得多；
3. Markdown 的图片/链接/双链插值**一律 `esc()`**。

护栏：`microbench/_test_tablet_hardening.js` [2]（6 条向量 + 实体/制表符绕过 +
双链别名），用**真的 HTML 属性解析器**判定（不能用 `/on[a-z]+=/` 扫 ——
属性值里出现 "onerror=" 只是文本，不是属性）。
**已做破坏性验证**：把 `E_AMP` 改回 `E_QUOT` → 测试立刻红；改回来 → 绿。

### B6　公式落在引用块/多行列表里 → 整篇笔记渲染崩溃

`extractMath` 在最外层把公式换成占位符，递归层自己的公式表却是空的 →
末尾回填时 `formulas[0]` 是 `undefined` → `renderMath` 抛 TypeError。

**连锁伤害**（这才是它要命的地方）：
`openNote` 抛异常 → `saveCurrent` 后半段的 `pushToDir` 不执行 →
「保存」只存了本地、没写回云盘，却照样弹「已保存」；
`pullFromDir` 末尾的 `openNote` 抛异常 → **整轮同步静默中断**。

修法：公式表**跨递归层共享** + `renderMath` 兜底 + `renderMarkdown` 外层
try/catch（渲染失败退回纯文本源码，宁可显示源码也别白屏）；
顺手删掉一处死代码（每个公式被 KaTeX 渲染两遍）。

护栏：`_test_tablet_hardening.js` [3]（引用块行内/块级、多行列表、嵌套列表）。

## 4. AI 面板（本轮按用户要求重做）

用户原话：**「点击发送之后，对话框里不要还保留问题，就是我的输入栏中不要还保留我问的啥」**

### 4.1 核心：发送后清空输入栏

```js
if (qBox) qBox.value = "";     // 取出来就清空 —— 在任何 await 之前
```

问题**不会跟着消失**：它作为一条「问：xxx」留在对话区里（用 `textContent` 赋值，
不会注入 HTML）。所以输入栏是干净的，历史还在。

### 4.2 顺带做的优化

| 改动 | 说明 |
|---|---|
| **多轮上下文** | 同一篇笔记的最近 3 轮问答会带上，追问时模型知道前文在讲什么（`system` 仍在最前面） |
| **Enter 发送 / Shift+Enter 换行** | ⚠ 必须判 `e.isComposing` —— 中文输入法选词时按 Enter 是「确认候选词」，不判断的话**选完词一按回车问题就发出去了** |
| **停止按钮** | 生成中才出现；APK 里走原生代理时也能停 |
| **清空对话** | 清对话区 + 清该篇的历史 |
| **「带上原文」提示条** | 从 PDF 划词过来时，让人看得见这次提问会带上哪一段（可一键去掉） |
| **换笔记自动切对话** | 只在**真的换了笔记**时清 —— 同步完成后会重调一次 `openNote`（同一篇），那时候不能把用户正在看的回答抹掉 |
| **删掉死代码** | `$("ai-question").value = kind === "ask" ? "" : "";` —— 三元两边一样，等于永远清空输入框 |

### 4.3 护栏

`microbench/_test_tablet_ai.js`（24 项）+ `microbench/_test_tablet_hardening.js`（29 项）：
输入栏清空、问题不丢、没配 Key 时不吞掉输入、提问不注入 HTML、
多轮上下文正确、`isComposing` 时不发送。

## 7. 本轮踩的坑（自己踩的，值得记）

| 坑 | 教训 |
|---|---|
| 用 `node -e "带引号的代码"` 跑校验 → PowerShell 把引号吃掉，报「意外的标记」 | AGENTS.md §2.2：**一律写脚本文件再跑**。这次又踩了第 5 次 |

| `subprocess.run(text=True)` 在中文 Windows 按 GBK 解码 node 输出 → emoji 路径直接 `UnicodeDecodeError` | AGENTS.md §4.9：显式 `encoding="utf-8"` |
